# Repository Reuse Rule

Before adding a dependency or creating a subsystem:

1. Search the target repository for an existing implementation.
2. Search this hub's curated and generated repository catalog.
3. Inspect candidate repositories natively through GitHub.
4. Check license, recent maintenance, security/dependency risk, framework compatibility, deployment complexity and overlap.
5. Classify each candidate as REFERENCE, LIBRARY, TEMPLATE, TOOLING or SERVICE.
6. Prefer the smallest integration surface.

Never replace a working canonical subsystem solely because a starred repository looks more modern.
